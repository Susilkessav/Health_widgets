Homeostat — Project Overview

1. What is Homeostat?

Homeostat is a personal health companion built around a living, customizable digital human avatar.

Instead of presenting health information primarily through charts, dashboards, and abstract scores, Homeostat converts the user's real health and activity data into an explainable visual state.

The long-term experience is:

Real health/activity data
        ↓
Personal calculations
        ↓
Semantic health state
        ↓
Visual avatar state
        ↓
Widget / app / Live Activity
        ↓
Contextual explanation or action

Example:

User slept less than usual
        ↓
Homeostat detects:
sleep = below_personal_baseline
        ↓
Avatar has subtly tired eyes
        ↓
User taps the eyes
        ↓
"5h 58m sleep
Your recent baseline: 7h 16m
Difference: -1h 18m"

The avatar is therefore not simply decoration.

It is the primary visual interface for the user's health state.

3. Core Product Principles

3.1 Deterministic core

Health calculations are performed by normal tested code.

LLMs never decide:

sleep duration
HRV baseline
resting-HR baseline
training load
movement state
confidence
health-state classification

3.2 Agentic edges

AI may later:

explain
summarize
suggest
plan
ask
perform approved actions

but it operates on structured state generated by the deterministic engine.

3.3 Explain everything

Every visual state must be traceable back to:

metric
value
baseline
difference
source
timestamp
confidence
calculation/version

The user should always be able to ask:

Why do I look like this?

3.4 Personal baselines over generic targets

Homeostat should primarily compare users with their own recent behavior, not arbitrary population targets.

Examples:

sleep vs your normal sleep
steps vs your normal movement by this time
HRV vs your normal HRV
resting HR vs your normal resting HR
training vs your recent training

3.5 Show uncertainty

Homeostat must never pretend missing data is known.

Example:

Sleep confidence:       high
Workout confidence:     high
Nutrition confidence:   low

The unknown nutrition state should remain unknown rather than generating a confident visual.

3.6 Sensors do not override the user

Measured state and subjective state remain separate.

Example:

Sensor context:
Typical

User reported:
Very tired

Homeostat may explain the disagreement but must not declare that the user is wrong.

3.7 Non-judgmental design

The product must not punish users.

Avoid:

dead/sick avatar
shame
broken streaks
body-size changes from food
body-size changes from exercise
sad face because recovery is low

The avatar reflects state without judging the person.

Example:

8. Temporary State vs Long-Term Identity

Temporary state

Changes over minutes/hours/days.

Examples:

sleepiness
sweat

Long-term identity

Changes over weeks/months.

Examples:

Long-term progress should primarily affect the avatar's world and personalization, not automatically alter body shape.

15. HealthState

HealthState represents semantic truth according to Homeostat's deterministic model.

Example:

{
  "sleep": {
    "state": "below_baseline",
    "severity": 0.62,
    "confidence": 0.97
  },

  "recovery": {
    "state": "typical",
    "confidence": 0.92
  },

  "movement": {
    "state": "ahead_of_usual",
    "confidence": 0.95
  },

  "workout": {
    "state": "recent_workout",
    "type": "strength"
  }
}

It contains no avatar artwork logic.

22. Agent Rules

Agents must not:

calculate health scores themselves
invent measurements
diagnose disease
recommend medication
silently change important plans

Every numeric claim must come from a tool result or deterministic state.

23. Agent Autonomy

Possible levels:

Level 1
Suggest

Level 2
Act after confirmation

Level 3
Low-risk reversible actions if enabled

24. Agent Memory

Store structured memory rather than unlimited conversational history.

Examples:

25. Personal Experiments

Later Homeostat can help users test personal questions such as:

Does stopping caffeine earlier improve my sleep?

Does walking after lunch improve afternoon energy?

Does training earlier affect sleep?

Does a consistent bedtime help me?

Experiments should include:

hypothesis

adherence

Avoid causal claims from simple observational correlations.

26. Smart Nudges

Homeostat should not simply send many AI-generated notifications.

Nudge decisions should use:

availability
recent behavior
notification cooldown
user preference
past nudge effectiveness

The agent may write the text.

The system decides whether a nudge should exist.

Raw time series should remain local or user-controlled whenever practical.

38. Final Architecture Rule

The most important architectural rule in the entire project is:

Health data describes what happened. Feature calculations derive the numbers. HealthState determines what those numbers mean inside Homeostat. AvatarState determines how that meaning appears visually. WidgetState determines what a surface needs to render. Agents may help explain or act, but never redefine the underlying truth.

Keep those layers separate throughout the project.
